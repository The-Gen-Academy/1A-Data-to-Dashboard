Build a Streamlit web app called "Ad Campaign Performance Analyzer."

CONTEXT
This is a marketing analytics dashboard for reviewing ad campaign performance
across social media platforms. The end user is a marketer who wants to quickly
see which campaigns and channels are performing best.

DATA
- The app should let the user upload a CSV file (default expected filename:
  social_media_advertising_sample.csv). Also include the file in the project
  root so the app can load it by default if no file is uploaded.
- Columns in the CSV:
  Campaign_ID, Target_Audience, Campaign_Goal, Duration, Channel_Used,
  Conversion_Rate, Acquisition_Cost, ROI, Location, Language, Clicks,
  Impressions, Engagement_Score, Customer_Segment, Date, Company

DATA CLEANING (do this on load, before anything else)
- Acquisition_Cost is stored as a string like "$500.00" — strip the "$" and
  commas, convert to float. Treat this column as "Spend".
- Duration is stored as text like "15 Days" — extract the numeric value into
  an integer column (e.g., Duration_Days).
- Date should be parsed as a proper datetime column.
- Conversion_Rate is a decimal (e.g., 0.15 = 15%) — keep it as-is but format
  as a percentage when displaying.
- Derive a Conversions column as Clicks * Conversion_Rate (rounded to nearest
  whole number), since raw conversion counts aren't in the data.
- Handle any missing/null values gracefully (drop or fill, whichever keeps
  the app from crashing) — do not let the app error out on bad rows.

METRICS TO CALCULATE (compute these as reusable functions, not just inline)
- Total Spend = sum of Spend
- Total Conversions = sum of derived Conversions
- CTR (Click-Through Rate) = (Total Clicks / Total Impressions) * 100
- CPC (Cost Per Click) = Total Spend / Total Clicks
- Conversion Rate (avg) = average of Conversion_Rate column * 100
- CPA (Cost Per Acquisition) = Total Spend / Total Conversions
- ROAS proxy = use the existing ROI column, averaged (label it clearly as
  "Avg ROI" in the UI since that's what the dataset actually provides)

LAYOUT

1. Sidebar (persistent across all tabs, filters everything below):
   - Date range picker (min/max based on the Date column)
   - Multi-select for Channel_Used (platform)
   - Multi-select for Campaign_Goal
   - Multi-select for Customer_Segment
   - A "Reset Filters" button
   - All filters should apply globally — every tab's charts, tables, and KPIs
     must reflect the currently selected filters.

2. Main area: use st.tabs() with these four tabs:

   TAB 1 — "Overview"
   - Row of KPI cards (use st.metric or styled columns) for: Total Spend,
     Total Conversions, Avg CTR, Avg CPC, Avg ROI
   - One line chart below: Spend vs. Conversions over time (dual-axis or two
     separate lines, aggregated by day or week depending on date range size)

   TAB 2 — "Platform Performance"
   - Bar chart comparing Spend, Conversions, and Avg ROI across Channel_Used
     (Facebook, Instagram, Pinterest, Twitter) — use grouped or faceted bars
   - A summary table below with one row per platform showing all key metrics

   TAB 3 — "Campaign Deep-Dive"
   - A searchable/sortable data table showing all campaigns with their
     metrics (Campaign_ID, Company, Channel_Used, Campaign_Goal, Spend,
     Clicks, Impressions, Conversions, CTR, ROI)
   - A funnel chart showing Impressions -> Clicks -> Conversions
     (aggregated across the currently filtered data)

   TAB 4 — "Trends Over Time"
   - A line chart with a dropdown letting the user pick which metric to plot
     over time: Spend, Clicks, Conversions, or ROI
   - Respect the sidebar date filter for the x-axis range

STYLING
- Clean, minimal, modern look — use Streamlit's default theming but make sure
  KPI cards are visually distinct (columns with borders or background shading)
- Format currency values with $ and commas, percentages with %, and large
  numbers with comma separators
- Add a short title and one-line description at the top of the app

TECH NOTES
- Use plotly or altair for charts (prefer plotly for interactivity)
- Use pandas for all data manipulation
- Keep the code organized into clear functions (load_data, clean_data,
  compute_metrics, render_sidebar, render_tab_overview, etc.) rather than one
  giant script — this will make it easier to debug and modify later
- Make sure the app doesn't crash if filters result in zero rows — show a
  friendly "No data for selected filters" message instead
